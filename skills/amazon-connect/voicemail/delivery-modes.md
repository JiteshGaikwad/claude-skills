# Voicemail Express (VMX3) — Delivery Modes

Voicemail Express (VMX3) is the open-source voicemail add-on for Amazon Connect (Amazon Connect has no native voicemail). VMX3 captures a recording in a contact flow, transcribes it, stores the audio in S3, generates a presigned URL for the recording, and then *delivers* the result to a destination. VMX3 supports three delivery modes:

1. **Amazon Connect Tasks** — voicemail arrives as a standard Connect Task.
2. **Amazon Connect Guided Tasks** — a Task rendered through an Agent Guide with an in-workspace audio player.
3. **Email via Amazon SES** — voicemail is emailed using a SES template.

The delivery mode is chosen per voicemail by contact attributes set in the voicemail contact flow. Each mode has its own example contact flow shipped with the solution, plus a small set of mode-specific optional contact attributes that override the defaults configured at implementation time.

In all three modes, the delivered payload includes the same core elements: the **transcript**, a **presigned URL** to the recording, the **customer callback number**, and **all other contact attributes** captured in the flow. For Guided Tasks and Email, an optional **generative AI summary** can also be included.

---

## 1. Amazon Connect Tasks delivery

Delivering voicemail as an Amazon Connect **Task** is the simplest delivery option to configure. Aside from making sure that queues and routing profiles in Amazon Connect are configured to allow Tasks, there is essentially no additional setup required. A task contact flow is provided as an example with the solution and is suitable for normal use.

### How it works

- Tasks are queued and presented to agents just as any other contact would be — they use native Amazon Connect Task routing.
- In the Task, the agent has access to the **presigned URL** for the voicemail recording.
- The **transcript** is presented as the **Task description**.
- **All other contact attributes**, including the **customer callback number**, are included in the Task information as well.

### What the agent sees / playback

The agent receives a normal Task. To listen to the voicemail, the agent opens the **presigned URL** (the recording link) included in the Task — playback happens outside the workspace via that link. The transcript is read directly in the Task description.

### Mode-specific contact attribute

There is one additional contact attribute that applies to this delivery model:

- **`vmx3_task_flow` (Optional)** — (Contact flow ID) the contact ID of a custom task flow used to process tasks generated by the voicemail configuration. If this is not provided, the default flow configured during implementation is used.
  - Example: `'vmx3_task_flow':'509a1915-cd54-4632-a923-6dafc5b722a9'`

### Configuration notes

1. In the **routing profiles** for agents who will handle voicemail Tasks, ensure **Task** is enabled in the **Set channels and concurrency** section.
2. Ensure the **individual queues** in the routing profile also have **Task** selected (for queues where voicemail is allowed).

### Pros / cons

- **Pros:** Simplest mode to configure; no Agent Guide or SES setup; uses native Task routing so it integrates directly with existing queue/agent routing.
- **Cons:** No in-workspace audio player — the agent must open the presigned URL to listen; the experience is a plain Task with the transcript as the description and a recording link.

## 2. Amazon Connect Guided Tasks delivery

Delivering voicemail as an Amazon Connect **Guided Task** is described as the **most secure and visual** option available. As with plain Tasks, aside from making sure queues and routing profiles are configured to allow Tasks, there is essentially no additional setup required. Contact flows are provided as examples with the solution and are suitable for normal use.

### How it works

- Tasks are queued and presented to agents just as any other contact would be, but with a **visual presentation using Agent Guides**.
- In the guide, the agent sees an **audio player UI** to listen to the voicemail recording **directly in the agent workspace**.
- The **transcript** is presented in a **collapsible section**.
- The **generative AI summary** is also presented in a collapsible section, **if that option was selected**.
- **All other contact attributes**, including the **customer callback number**, are included in the Task information.

### What the agent sees / playback (the Guide UI)

The voicemail is rendered through an **Agent Guide** in the Amazon Connect agent workspace. The guide provides:

1. An **audio player UI** for in-workspace playback of the recording (no need to open the presigned URL externally for normal use).
2. A **collapsible transcript** section.
3. A **collapsible generative AI summary** section (when the gen-AI summary option is enabled).
4. The remaining contact attributes / Task information.

### Mode-specific contact attribute

There is one additional contact attribute that applies to this delivery model:

- **`vmx3_guided_task_flow` (Optional)** — (Contact flow ID) the contact ID of a custom task flow used to process tasks generated by the voicemail configuration. If this is not provided, the default flow configured during implementation is used.
  - Example: `'vmx3_guided_task_flow':'509a1915-cd54-4632-a923-6dafc5b722a9'`

### Configuration notes

1. In the **routing profiles** for agents who will handle voicemail Tasks, ensure **Task** is enabled in the **Set channels and concurrency** section.
2. Ensure the **individual queues** in the routing profile also have **Task** selected (for queues where voicemail is allowed).

### Differences from plain Tasks

- Adds a **visual Agent Guide presentation** on top of the Task.
- Provides an **in-workspace audio player** for playback (plain Tasks rely on opening the presigned URL).
- Presents the transcript (and optional gen-AI summary) in **collapsible sections** rather than as the raw Task description.
- Considered the **most secure and visual** of the delivery options.

## 3. Email delivery via Amazon SES

Email delivery sends the voicemail to an email address using **Amazon Simple Email Service (SES)**. From an AWS perspective it is fairly straightforward: once you have validated the email domain/addresses (during the email-delivery prerequisites/setup) and configured queue emails appropriately, there is little else to manage. The main ongoing effort is creating additional **email templates** where required.

### Routing emails to agent email addresses

The agent email address field is **selectable on deployment** and can be one of: **`Email`**, **`SecondaryEmail`**, or **`Username`**.

- For **SAML** implementations, use either `SecondaryEmail` or `Username`.
- Other implementations may use whichever field is appropriate.
- The agent's email address must be present in one of these fields.

### Mode-specific contact attributes

There are three additional contact attributes that apply to this delivery model:

- **`vmx3_email_from` (Optional)** — (email address) the address to send the voicemail **FROM**. If not provided, the default FROM address configured during implementation is used.
  - Example: `'vmx3_email_from':'my_company@example.com'`
- **`vmx3_email_to` (Optional)** — (email address) the address to send the voicemail **TO**. If not provided, and it cannot be determined by looking at the agent or queue data, the default TO address configured during implementation is used.
  - Example: `'vmx3_email_to':'my_company@example.com'`
- **`vmx3_email_template` (Optional)** — (template name) the Amazon SES email template to use when sending this email. If not provided, the default email template configured during implementation is used.

### What's in the email — standard template data

The standard configuration passes a few key data elements by default. These values may not be part of the contact trace record; they are set by the **VMXPackager** Lambda function. They can be referenced in any custom template without additional configuration:

- **`vmx3_from`** — the phone number the customer called from or provided as a callback number.
- **`vmx3_agent_name`** — the name of the agent the voicemail was intended for (for emails routed to a specific agent).
- **`vmx3_presigned_url`** — the presigned URL of the voicemail recording.
- **`vmx3_transcript_contents`** — the transcript of the voicemail.

A generative AI summary variable (**`vmx3_genai_summary`**) is also referenced in the provided HTML template.

In SES templates, variables are referenced with **double curly braces**, e.g. `This is a voicemail for {{entity_name}}.`

### Using custom data in templates

Because **all contact attributes** are passed along as data with the email request, you can use **any** contact attribute value in your templates, referenced the same way as standard attributes. For example, a custom attribute `customer_level` is referenced as `Voicemail from a {{customer_level}} customer.`

### HTML layout of the provided template

The shipped HTML template renders, top to bottom:

1. A **header banner** (`<div>` with a solid background color and `sans-serif` font) containing the Amazon Connect logo image and an **"Amazon Connect Voicemail"** heading in white text.
2. A line: **"You have a new voicemail from `{{vmx3_from}}`."**
3. A link: **"Listen to the voicemail."** pointing to `{{vmx3_presigned_url}}`.
4. A **"Generative AI Summary:"** heading followed by `{{vmx3_genai_summary}}`.
5. A **"Voicemail Transcript:"** heading followed by `{{vmx3_transcript_contents}}`.

The full HTML body shipped with the solution (with the inner double-quotes escaped so it is valid as a JSON string value for `template_html`):

`Dear {{vmx3_agent_name}}, A voicemail was left for you from {{vmx3_from}}. You can listen to the message via the following URL: {{vmx3_presigned_url}}.`

### Managing email templates (VMXSESTool Lambda)

SES only provides **programmatic or CLI** methods for managing templates — there is **no GUI**. To make this easier, VMX3 ships the **VMXSESTool** Lambda function for creating, modifying, and deleting templates. You are not required to use it, but it removes the need to write new code.

You invoke the function by creating **test events** that tell it which method to run and pass the required data. Test event fields:

- **`mode`** — `create` | `get` | `update` | `delete`. Defines the operation: create a new template, get an existing template, update an existing template, or delete an existing template.
- **`template_name`** — (string) the name of the template.
- **`template_subject`** — (string) the email subject. May include attribute keys in double curly braces.
- **`template_text`** — (string) the plain-text version of the email (used by plain-text clients). May include attribute keys in double curly braces.
- **`template_html`** — (string) the HTML version of the email (used by HTML-capable clients).

### When to use it

- Delivering voicemails to a **shared mailbox** or **distribution list** rather than a live agent/queue.
- Routing to a **specific agent's email** (using the deployment-selected `Email` / `SecondaryEmail` / `Username` field), including SAML setups.
- Scenarios where asynchronous, email-based handling is preferred over Task-based agent routing.

## Comparison: Tasks vs Guided Tasks vs Email

| Dimension | Amazon Connect Tasks | Amazon Connect Guided Tasks | Email (SES) |
| --- | --- | --- | --- |
| **What the agent sees** | A standard Connect Task; transcript shown as the Task description; presigned URL and all contact attributes (incl. callback number) in the Task info | A Task rendered via an Agent Guide; audio player UI, collapsible transcript, optional collapsible gen-AI summary, plus contact attributes (incl. callback number) | An email built from a SES template containing a "listen" link to the presigned URL, optional gen-AI summary, transcript, and callback number |
| **Where playback happens** | Outside the workspace — agent opens the presigned URL | In-workspace via the Agent Guide's audio player UI | Outside — recipient clicks the "Listen to the voicemail" link (presigned URL) in the email |
| **Routing** | Native Connect Task routing to queue/agent | Native Connect Task routing to queue/agent, presented via an Agent Guide | Sent via SES; TO resolved from `vmx3_email_to`, or agent/queue data, or the default; FROM from `vmx3_email_from` or default; agent email field selectable at deploy (`Email`/`SecondaryEmail`/`Username`) |
| **Mode-specific attribute(s)** | `vmx3_task_flow` (optional custom task flow) | `vmx3_guided_task_flow` (optional custom task flow) | `vmx3_email_from`, `vmx3_email_to`, `vmx3_email_template` (all optional) |
| **Prerequisites** | Routing profiles + queues allow **Task** (channels/concurrency + queue Task enabled) | Routing profiles + queues allow **Task**; Agent Guide presentation (example flows provided) | Validated SES domain/addresses; queue emails configured; agent email in the selected field; optional custom SES templates |
| **Template/UI management** | None beyond the example task flow | None beyond the example flows/guide | SES templates managed programmatically/CLI or via the **VMXSESTool** Lambda (no SES GUI) |
| **Setup complexity** | Lowest | Low (example flows provided) | Medium (SES validation + template management) |
| **Notable characterization** | Simplest delivery option to configure | Most secure and visual option | Best for shared mailboxes / distribution lists / specific agent email, incl. SAML |
| **Best-fit use case** | Drop voicemails into existing queue/agent Task routing with minimal setup | Richest agent experience: in-workspace playback + transcript + optional AI summary | Email-based or asynchronous handling, shared mailbox/distribution list delivery |

### Cross-cutting notes

- All modes deliver the same core data: transcript, presigned recording URL, customer callback number, and all captured contact attributes.
- The **generative AI summary** is available to Guided Tasks (collapsible section) and Email (template variable `vmx3_genai_summary`) when that option is selected.
- Each mode's destination/behavior is driven by per-voicemail contact attributes; when those optional attributes are omitted, the defaults configured during implementation are used.
